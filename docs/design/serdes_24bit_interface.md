# TX/RX 的 24-bit 并行接口

首选把 **24 bit × 250 MHz** 放在 TX/RX 主机侧，两个方向都用 `valid/ready`。保留单条差分线和四相数据通路。4 Gb/s 先沿用两端的 16-bit 串解串，在数字边界做字宽转换。5 Gb/s 可让 TX 局部继续用 16:4，RX 独立评估 20-bit 字域和 125 MHz CDR。[单路 TX 草案](tx_5g_word_interface.md) · [升级时序证据](../../results/catalog/ppa_upgrade_review_20261124.json)

## 总线频率与字宽

| 线速 | 24-bit 主机口保持 250 MHz | 若串解串器直接每字交付 24 bit |
|---|---|---|
| 4 Gb/s | 平均每 3 拍传 2 字 | 166.667 MHz 字域，1 GHz 四分之一速 ÷6 |
| 5 Gb/s | 平均每 6 拍传 5 字 | 208.333 MHz 字域，1.25 GHz 四分之一速 ÷6 |

24 bit × 250 MHz 的总线峰值为 6 Gb/s。上表按原始线速换算平均有效拍比例，接收频偏、协议开销和主机等待会改变实际有效拍分布。PLL 反馈按半速 VCO 与参考之比设置，250 MHz 参考下 4/5 Gb/s 分别为 ÷8/÷10。字域 ÷6 在四分之一速时钟上实现。[项目规格](../overview/spec.md)

## 主机口扩宽时的数据路径

- **TX** 在主机侧收 24-bit 字，跨域 FIFO 一次传一个完整字。在 TX 本地字域转换成 16-bit 后交给串化器。TX 空间有限时向主机撤 `ready`；训练和空闲由线侧发射状态机处理。
- **RX** 在恢复字域依次完成采样、CDR、字对齐和 24-bit 拼包，然后跨域给主机。恢复采样持续推进。主机短暂停顿由 FIFO 吸收，满后按既有错误与重训语义处理。空 FIFO 对应 `valid=0`，主机等待时保持已经展示的字。

16↔24 的共同组为 48 bit，两个主机字对应三个 16-bit 字。bit0 先发时，`H0/H1` 依次形成 `H0[15:0]`、`{H1[7:0],H0[23:16]}`、`H1[23:8]`。20↔24 的共同组为 120 bit，即六个 20-bit 字和五个 24-bit 字。首版可用固定切片和组内计数完成拼包。RX 在训练标记后对齐首个载荷 bit，同时归零拼包计数。复位、掉锁及速率切换丢弃未完成的组并开始新纪元。[现行 RX 字序](../../digital/pnr/rtl_v3/rx_word_map.sv) · [RX 主机域](rx_word_host_timing.md)

RX 先拼成 24 bit 还有吞吐收益。若让 250 MHz 主机侧每拍只从 16-bit FIFO 取一个字，接口会限在 4 Gb/s。5 Gb/s 下每个尚空的 24-bit FIFO 槽约可缓冲 4.8 ns 的连续输入。深度按最坏停顿、初始占用和跨域指针延迟确定。

## 串解串器也采用 24-bit 字时

四相各分配六个时隙。第 `p` 相按 `p,p+4,…,p+20` 取位，TX 需要 6:1 串化和确定启相的 ÷6，可先比较 ÷2 后接 ÷3。RX 各相收六组数据/边沿，输出 `wd[23:0]` 和 `we[23:0]`。仍保持 `we[0]` 位于上一字 `wd[23]` 与本字 `wd[0]` 之间。模拟 RX 至数字接口因此从 32 扩到 48 条信号，字对齐偏移扩为 0–23。[现行 TX 四相映射](../../analog/tx/sst/spice/tx_sst_serializer16.spice) · [现行 RX 解串网表](../../analog/rx/cmos_rx/spice/rx_cmos_deser16.spice)

若 CDR 每两字更新，则一拍处理 48 UI，5 Gb/s 下为 9.6 ns、104.167 MHz。以 64 码覆盖 2 UI 和现有限幅 0.75 步/拍计算，理论频偏上限约 ±488 ppm，±300 ppm 需 0.461 步/拍。每字投票的 ±24 和两字合计的 ±48 仍可分别放进现有 6、7 位有符号口。投票树、增益、失锁窗口和实际 CDR 频偏回归仍需按新节拍重做。[CDR 实现](../../digital/pnr/rtl_v3/cdr_phase_frequency.sv)

## 原型复核

隔离位序模型在随机停顿下双向重排 24↔16 的 96,000 bit 及 24↔20 的 240,000 bit，每个方向均逐位一致。隔离 Icarus 复用了原有 FIFO 压力台，扩为 24 bit 并变化高 8 位，通用 FIFO 通过满空、停顿、指针回卷和复位。v3.2 的时序优化 FIFO 在同台首字读出 `xx1000`，预期为 `6c1000`，16-bit 对照通过。其存储更新、预取选择及输出暂存有固定 16-bit 分片。首版可用已通过行为检查的通用 FIFO，随后以目标时钟做 STA，再决定是否按字节扩展 v3.2 分片。[通用 FIFO](../../digital/rx/rtl/rx_async_word_fifo.sv) · [v3.2 FIFO](../../digital/pnr/rtl_v3/rx_async_word_fifo.sv) · [压力台](../../digital/rx/tb/tb_rx_async_word_fifo.sv)

## 固定 256 bit 存储时的 24/32-bit 管理开销

另一种做法保留 v3.2 的 16 槽 × 16 bit，在现有 16-bit 端口外放单时钟 `valid/ready` 字宽转换。以下是同一份过滤后的 SKY130 HD TT Liberty 下的单元面积增量。包含每方向 16 bit 的暂存余数、选择逻辑和相位状态，FIFO 本体仍为 256 bit。16-bit 直接连接的对应增量为 0。

| 口宽 | FIFO 本体容量折成总线整字 | TX 写入适配增量 | RX 读出适配增量 |
|---:|---|---:|---:|
| 16 bit | 16 字 | 0 | 0 |
| 24 bit | 10 字，余 16 bit | 996 µm² | 946 µm² |
| 32 bit | 8 字 | 762 µm² | 589 µm² |

同尺度下 v3.2 的 16-bit FIFO 综合面积为 17,972 µm²。每方向新增面积约为该 FIFO 的 3.3%–5.5%。32-bit 按两个整半字转换，24-bit 跨边界需要三相切片与字节拼接，因此本例的 32-bit 管理前后合计比 24-bit 低约 30%。四个转换原型均在随机停顿下逐位核对并检查了停顿保持。数值是单时钟逻辑综合，额外 CDC、多端口读写、引脚和布线待实际接入后计入。单端口每拍传 16 bit 时，5 Gb/s 需要至少 312.5 MHz 的 FIFO 窄侧有效时钟。[综合和行为收据](../../results/catalog/fifo_fixed_storage_width_20261124.json)
