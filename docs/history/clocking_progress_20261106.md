## 测量与运行工具改进

- 公共函数 `serdes_flow.clock.binary_counter` 在相邻有效时钟沿中点读状态，检查整个窗口内每次模 8 递增。旧检查允许最后一次错步之后再计 16 周期即报告正常；现在窗口内有任意错步都不报告计数正确。
- `clock_replay/counter.py` 继续分别测量 clk→q、建立和保持；原生调用传入实测 UI。状态检查不代替时序与毛刺验收。
- `native_clock/r5_v3.py` 增加 `--resume`、`--analyse-only`、逐条件完整性检查和逐完成工况的原子汇总。重试用 `.rN` 新目录；恢复时使用原 deck 与激励，变更 DUT 或工作点必须另起 campaign。
- 再分析写入新 `analysis/<UTC>/`，保留原日志和已有运行。缺失、超时和分析错误保留独立状态，单个缺失点不再阻断其他结果。

旧回放 `counter/v3_probe_20261031T135020Z` 的 15 个工况也按新规则复查：14 个在完整 14–30 ns 窗口连续计数，FS 1.65 V 85°C 在窗口最初出现 `3→0→1→2…`，约 14.85 ns 的采样点起进入正确序列。这一次错步现明确报告为窗口内计数失败；它与另一次、较晚窗口的数据眼图验证分开记录，不能把稳态眼图通过当作启动全过程通过。复查数据和波形 SHA256 同样存入本轮快照。

验证：计数器合成波形覆盖 clk→q 60/101/180 ps、漏计后连续正常超过 16 周期、无时钟，以及真实 SS 热 hh 波形回归；连同 SPICE 输出与文档链接，共 10 项检查通过。

## 复现

只用已入库数据重画，不需要 ngspice 或本机大波形：

```bash
uv run python verification/plotting/current_clocking.py
```

从显式列出的原始结果重新采集快照并绘图：

```bash
uv run python verification/plotting/current_clocking.py --collect
```

从原生 campaign 提取完整工况（不启动仿真）：

```bash
uv run python analog/tx/serializer/tb/native_clock/r5_v3.py probe \
  --resume results/analog/tx/serializer/native_r5_v3/20261106T121036Z --analyse-only
```

补缺失工况可用相同命令去掉 `--analyse-only`，但先按下面的收敛诊断处理 FF 冷角，避免原样再耗一小时。

## 适用范围

VCO 工作区和 CP 图为 45 MOS/V/T × tt/hh/ll，真实偏置与 PDK 电阻；hh/ll 是 RC 联合角，未覆盖 hl/lh。工作区频率交点和局部斜率由离散仿真点插值，并非目标电压的精确仿真。七工况相噪结果不因工作区扩大而自动扩展到 135 条件。

原生前端＋分发数据为 8 个完整压力工况、静态并行数据、开环 Vctrl、无失配和提取寄生；尚未做实际字寄存器、动态数据眼图、位映射或原生闭环。内部节点有超过 400 mVpp 的记录，I-17 的逐节点符合性仍未关闭。单元 215 mVpp 仅是本次 W20 扫描参考，不替代项目规格。
