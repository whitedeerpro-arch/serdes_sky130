# VCO三组共同码补测：固定码静态覆盖补齐

原工作图给出42/45组（MOS×VDD×无源角）三温共同码。补测原缺失三组高温候选码后，三组均在实测CP上沿以内跨越2 GHz；合并后为45/45。无需为这三处缺测先增加阵列位数或强制温漂切码。结果只覆盖开环固定码静态调谐，不是锁定、上电、实际CP/LF交接、失配或噪声结论。现行数值和图见[VCO设计](../design/pll_vco.md#固定码三温补测2026-11-07)。

## 为何原记录少三组

`workmap.py extend`只挑原0.85/1.1/1.35 V附近的码，又限制新增电压≤VDD−0.4 V；FF 1.95 V tt code7、FF ll code12、FS ll code7的高温段未进入扫描。原扩展最高只测1.50 V，统计读取CP上沿1.60–1.66 V时，`np.interp`返回最末测点的频率，既非该上沿实测也非外推。原`extend.json`保持不动，其42是已知覆盖下界。

1/f码轴插值在0.85–1.35 V窄窗口的三温交集为空；这个模型结论不能推广到更宽CP窗口，也不能据此立即增加半码。先补共同整数码，成本低且能区分数据缺项与结构缺陷。[WP-006历史输入复核](../work_packages/deliveries/WP-006/resolution_tradeoff.md)保留拟合、残差及未知项。

## 补测与边界

`results/analog/pll/vco/cp_edge_fill/20261107T102145236159Z`含三deck、12个新增24 ns点：三个高温组合分别固定7/12/7，Vctrl为0.85、1.50、CP上沿−50 mV、CP上沿。真实偏置、PDK R、四缓冲/每端30 fF，末5 ns测频。先做0→1.001 ns独立冒烟；默认单worker，主控与TX仿真合计不超过2个ngspice。

12点均完整，三个deck无执行/日志失败。高温FF tt、FF ll、FS ll的2 GHz夹区分别为0.85–1.50、1.50–1.55、1.50–1.55 V；CP上沿为1.61/1.60/1.60 V。旧同码冷/常温24个点均重读完整raw。旧/新物理前缀忽略被控制段覆盖的DC默认值和温度后相同，所有实际include内容相同；采集器还核对每点控制电压、温度和四个码位，未用文件名替代控制值验证。旧FF部分deck有cosh等失败匹配记录，逐点附上所属日志状态，未清空或称为干净重跑。

FF tt高温交点的夹区较宽，1.489 V是稀疏线性插值，只说明静态可达，后续须细化实际工作点。对应上界测点比CP上沿低110 mV；另两组低50 mV。不能将插值余量直接当动态、失配或闭环余量。

## 运行工具复核

Terra交付准备/续跑脚本与图采集器，仿真配额0。主控review发现resume分组计时引用未定义`pts`，改按缺项数计时；补mock实际执行组装路径、截断冒烟拒绝和非有限测量不complete。只渲染的`--check`不能覆盖执行路径，故保留相应回归。

图采集器首次将首保存点严格要求≤19 ns，实际二进制跳过启动后首点在19 ns后0.56–1.17 ps，属于2 ps步长内的正常保存行为。修为最多容许一个步长，仍拒绝缺失20 ps窗口，新增回归；没有重跑电路。物理边界一致性及缺点不跨越插值也有回归。数据在`docs/data/vco_cp_edge_fill.json`、索引在`results/catalog/vco_cp_edge_fill.json`，旧记录未改写。
