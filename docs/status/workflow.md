# 项目工作流

目标是让每一轮工作解除一个明确的设计阻塞，并留下下一位可以直接使用的结果。技术主线遵循 [Fable 的架构决定](architecture_decisions.md)；Codex 负责工作组织、基础设施、局部实现与复核，发现反例反馈到受影响模块。总体完成条件见[项目目标](serdes_completion_goal.md)，当前优先级只在[执行计划](prelayout_plan.md)维护。

## 任务从哪里来

每轮从执行计划选择最靠前且依赖已满足的一项。问题表保留风险与稳定编号，工作包承载可独立执行的交付；二者都不是另一个项目待办表。已有工作包只有确实解除当前里程碑阻塞时才派发。旧修订的探索不因已有脚本或空闲名额自动恢复。

默认同时推进一条主线和至多一条直接支撑它的局部工作，例如原生闭环与叶单元寄生校准。独立的只读检查不占此限制，但不能产生另一条未经采用的电路主线。需要扩大同时在做的范围时，在计划中写清原因和依赖。此限制约束任务切换；仿真进程仍按全机资源单独分配。

## 一项任务的闭环

| 环节 | 必需内容 | 退出条件 |
|---|---|---|
| 定义问题 | 所属模块/里程碑、要判定的问题、已有证据、输入与实际源/负载、可编辑文件 | 可以明确说明哪种结果会改变下一步选择 |
| 选择实验 | 器件可实现性/寄生、约束模型、候选及预测、压力点和测量窗口 | 最小实验能区分候选或失效机理；门槛已有出处 |
| 执行 | 原身份续跑或新追加目录；先冒烟；记录模型、配置、工况、终点与成本 | 数据完整性可验证；失败和缺测保留 |
| 判断 | 比较预测与实测、眼图与位映射、功能/数值问题、通过范围和剩余风险 | 给出采用、继续迭代或停止该候选的结论 |
| 接受与接手 | 独立复核、受影响接口、需更新的工作修订与当前状态、下一个具体动作 | 别人不依赖聊天记录就能继续；候选未通过不能改为采用 |

普通局部工作可直接写入已有模块迭代记录，不要求额外建立工作包。跨人/跨 agent 交付才使用[任务模板](../work_packages/templates/task.md)和现有 evidence/review 机制；任务既定范围内的可逆工作直接执行。架构、规格或预算变更由 Fable/所有者作决定，先准备可审阅的结果和影响说明。

## 证据与任务状态分开

| 维度 | 用法 |
|---|---|
| 计划任务 | 待释放、可执行、执行中、待复核、已交付、阻塞、延后；“阻塞”必须附所需输入及解除动作 |
| 工作包机器状态 | 沿用 `waiting/ready/running/submitted/accepted/changes_requested`；不另加不受现有工具支持的值 |
| 结果 | 通过、功能失败、数值未完成、未测、ungraded；结果指明修订、实际驱动、偏置/RC、负载、场景、窗口和判据 |

`accepted` 只表示接受该交付；仿真执行完毕、DRC/LVS通过、无噪声短窗零错分别只证明各自的事。整颗通过不能由不同版本/不同输入的通过数相加得出。初值辅助、启动脉冲、预充捕获与真实上电分别记录，不能互相转移资格。

## 验证与资源

结构或尺寸问题按器件/寄生 → 约束模型 → 局部压力点校准 → 受影响接口 → 必要全角推进。中等难度修补同时比较替代结构，是否改变主线由架构决定。整机长仿真只回答明确的联合问题；不能作为每次局部修改的固定步骤。

全机 ngspice ≤4；没有固定“每人四个”或永久2+2分割。开跑前核对[资源登记](../work_packages/collaboration.md)和实时进程，由集成者安排 worker 与内存预算。长 campaign 按条件续跑、传真实 `t_end`、边界优先；健康检查用 `watch`，慢扫描先用 `audit` 区分超时/截断/中断/未启动。MC 保持样本、seed、chunk 与配对身份，测量复用公共库。具体命令见 [AGENTS.md](../../AGENTS.md)和[统计方法](../verification/statistics.md)。

## 一次结果发布只更新必要位置

先保存追加式运行与小数据索引，再在模块设计文档写结论和适用边界。接受后更新 [current.md](current.md) 的该模块和证据链接；电路被采用才更新 `*_working_revision.toml` 选择/参数。随后只更新计划中对应任务、受影响的问题编号和工作台引用。过程笔记进历史，不把所有汇总页各抄一遍。

工作台的层次、边界、模型与资料路径手工维护；当前验证数字链接到 current.md，`catalog.js` 由既有导出命令生成。历史证据中的参数和结果不批量改写；旧配置中用于兼容/追溯的指标保留，新增长篇状态文字改用链接。

## 汇报与停止条件

按交付/阻塞汇报：本轮解决的问题、决定及依据、仍开的风险、下一步和资源成本。不使用整机完成百分比，不用已跑点数代替设计进展。主线任务连续遇到相同阻塞时，整理最小反例和可选方案，转给架构决策；不要继续扩大相同长扫描。

收尾时更新协作页的活跃范围、仍在跑的命令/campaign/worker、续跑方法、未提交文件和下一动作。需要停止进程时只处理自己负责且已明确识别的任务。交接不要求顺手提交其他人的工作。
