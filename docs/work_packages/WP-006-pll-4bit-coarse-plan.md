# WP-006：PLL r5 四位粗调捕获规划

目标是形成可独立复核的低成本行为模型与参数计划，为现有 PLL 顶层补充未来粗调控制提供依据；本包不采用电路、RTL 或配置修改。交付者应使用 [证据](deliveries/WP-006/evidence.json)、[摘要](deliveries/WP-006/summary.md) 和[交接](deliveries/WP-006/handoff.md)，集成者独立复跑、review 后决定是否采纳。

## 边界和输入

对象为 r5 四位 0–15 码，码增大频率降低，细调正斜率。现有 [三位策略](../../config/vco_coarse_calibration.toml) 的 0–7 上限只代表历史设计政策，不是现行控制器实现。现有 [码表](../../config/pll_code_table.json) 是台架工作点，不是启动控制器 ROM 或全温固定码。输入及 SHA-256 在 evidence 中；135 条件为五 MOS 角、三电压、三温度、三个无源角。工作图使用真实偏置、PDK 电阻、环及四缓冲和 30 fF 负载，24 ns 点的末 5 ns 测频；不是原生闭环或上电结果。

[workmap.py](../../analog/pll/vco/tb/tuning/workmap.py) 先用 0、6、15 码的 1/f 二次拟合选码，再实际仿真候选码。证据仅将 summary 内真实仿真的码作为测量点，2 GHz 落点及局部斜率由相邻 0.25 V 点线性插值/割线得到，不把未测码拟合值称为实测。可行码是实测码集合中的候选，不能断言未测码均不可行。固定窗口的码表选择用 0.9 V 至 VDD−0.45 V 的斜率优先政策；表中电压已四舍五入。证据每条件列出码、插值电压、割线、固定窗口两侧余量和 1.1 V 的实测频率。

## 建议的行为模型和交付

1. 以 bias/pre_ref 有效、双节点预充与 CP/PFD 门控为前提，在测频和切码状态中明确控制 Vctrl、反馈计数器与 CP 的归属。现有启动监督器已有预充、释放、ACQUIRE/TRACK/FAULT，频率及相位质量前端未实现；模型应明确新粗搜与其接口及交接，不假设已有控制器。
2. 从确定初值出发，1.1 V 预充测频，太快则码 +1、太慢则码 −1，单步限幅 0…15，不回卷。每次切码等待经验证的模拟稳定时间后重新计数；禁止凭无效、超时或不稳定测量移动码。频率接近目标时，结合实际细调范围、检测误差及邻码重叠判定可交接；交接时按验证后的顺序释放预充、启用环路，冻结粗码。单调搜索到端点仍超范围时报告范围不足；不把范围不足当锁定。
3. 定义允许停止态：细调接管待锁（不等于锁定）、经独立质量判据确认的 TRACK、端点范围不足、测量无效/超时或稳定超时故障。超时与失败不能静默降级为成功。背景重校准暂不启用；若未来引入，必须有 Vctrl 内外迟滞、越界连续确认、切码最短驻留、切码干扰与重新稳定，以及防止与环路相互争用的顺序。
4. 实现可移植的纯数字/数学模型，覆盖 0/15 端点、上/下方向、相邻阈值、量化歧义、无效测量、不可达以及单可行码工况；输出输入身份、各状态和结果。评估 135 条件，区分真实测点与插值，不能外推缺失码。拟定窗口、容差、预充/保持和超时的推导式及待测值，不宣称签核。
5. 报告需要补测的切码毛刺与单步稳定、B2 在负载变化后重新稳定、CP/LF 接管、噪声和原生闭环/上电。历史42组加补测3组的45/45静态跨温结果不能被表述为启动覆盖；先按实际细调范围与动态稳定/测量不确定性设计交接，不把旧frozen_bad当不可达证明。

## 计数分辨率初算

参考频率 250 MHz，反馈为 VCO ÷8。Nref 个参考周期内，有限边沿计数相对理想计数误差以 ±1 count 为界，则折算 VCO 频率的量化误差界为 **8 fref/Nref = 2 GHz/Nref**。现有 1.1 V 相邻实测码对中最小间距 51.51 MHz，若仅要求单次误差界小于半间距，Nref > 77.65，即至少 78 周期；若要求小于四分之一间距，至少 156 周期。这只是量化分配示例，未计参考误差、抖动、异步采样、边沿丢失、稳定等待或判定迟滞；需具体架构与动态数据后确定，不是捕获时间或签核值。测得的 539 对并不覆盖所有码/条件。

## 复核与验收

运行 `uv run python verification/work_packages/wp006_pll_coarse.py` 重建证据，检查源哈希、135 行、可行码计算及跨温引用。提供模型源码、运行方法、每状态测试与失败案例、参数及未分级缺口；由集成者独立审阅。不要改 `config/work_packages.json` 或现有设计结论。
