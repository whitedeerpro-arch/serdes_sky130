# 常驻仿真与窗口波形采集

状态：ngspice47的小规模RC验证已完成。采用同一进程连续求解，批处理raw输出经POSIX FIFO送入会话内采集器，外部环形缓冲保存触发前历史及触发后窗口。尚未封装通用交互服务，未改动SerDes既有运行方式，也未新增持久化Python脚本。

电路状态和输出历史分别处理：电容电荷、积分历史、器件状态由求解器持续保留；只丢弃不需要的输出波形。不能从“只观察T±dt”推出系统没有更长物理记忆。测试中特意使用1 µs的慢RC，1000 ns时仍正确得到约0.63212 V，证明丢弃早期输出没有重置慢状态。

## 已验证路径

1. 网表使用.save提前选择端口，不含.control。
2. 以ngspice -b -r FIFO -o log运行，二进制raw数据直接流出，避免plot累计全部输出。仅使用.control做stop/resume并导出片段，不会自动释放既有plot历史。
3. 采集器按时间保留前2 ns环形数据，接收两个预定4 ns窗口，并用v(slow)上穿0.5 V触发第三个±2 ns窗口。无关数据流出后丢弃，完整raw不落盘。
4. 每约250 ms报告实际模拟时间/UI、进度、点数、近期推进速率、ETA和仿真进程RSS。ETA基于近期实测速率，不是固定每ns开销保证。

本机非可寻址FIFO有已验证的格式细节：raw头的No.Points保持0，末尾附加ASCII总点数。采集器检查实数记录宽度、单调时间、最终时刻及尾部计数；不能把它当作普通可寻址raw文件直接读取。

## 实测

- 连续2 µs=8000 UI，1000023个时间点；time和三个电压。
- 三个保留窗口各2000点，与完整参考逐点相同。
- 前视历史2 ns，环形上限8192点，实际峰值1022点；仅数值载荷约32 KiB，未包含解释器/对象开销。
- 仿真进程稳态RSS约10.5 MiB，采样期间不随点数增长。这是小RC结果，不能作为SKY130大电路的固定内存预算。
- 一次性完整参考约32 MB，比较后删除；保留窗口、日志、进度、源网表和校验摘要。

## 用于SerDes时的约定

提前选择CML/CMOS时钟、数据、PI控制和状态信号。可按已知时间或运行事件选择窗口，例如回卷或质量状态变化；丢弃后不能追溯查看未保存的任意旧节点。若自适应时间步过密导致点数上限不足，必须报告窗口覆盖不完整或停止采集，不能默默缺失触发前历史。

这种方法减少波形内存、磁盘和重复启动开销，不跳过电路演化，也不消除矩阵求解开销。当前验证的是连续长跑的有界输出采集；交互修改控制量、与RTL反馈、状态快照跨进程恢复需分别验证，不能由本测试推出。

原理依据：[ngspice内存说明](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf)、[save命令](https://nmg.gitlab.io/ngspice-manual/interactiveinterpreter/commands/save__saveasetofoutputs.html)。
